# Browse a reading-help corpus

The [reading-help corpus view](../reading-help/corpus/) opens a separately governed catalogue. Supply its `okf-reading-help-catalogue.v1` manifest URL, select a manual family and document, then select one passage. Search the document's declared paragraph numbers and labels to find a topic. Exact abbreviation search uses source-verified occurrence literals listed in that document's index; any proposed meaning stays separate. The view loads the catalogue, that document's index, only the leaves named by the passage, and its frozen page extraction. It does not load every document or turn candidate terms into guidance.

The consumer checks each document index against its declared byte count and SHA-256. Each gzip leaf has separate checks for its compressed and decoded bytes. It joins all segments in order, verifies the complete passage hash, and compares the displayed wording, occurrence spans and printed reference rows with the frozen page extraction. Missing or changed bytes stop that passage from opening. An `extraction_blocked` page means machine text was unavailable; it does not mean the PDF page is blank. A selected passage may use up to 32 segments; one larger passage does not prevent browsing the rest of its document.

Verified source bytes stay in a browser-session cache capped at 16 MiB and 64 entries. The selected passage reports its fetched files, fetched bytes and verified cache hits, so a repeated load can be compared with the first load. Opening a passage fetches its document's frozen extraction, bounded to 8 MiB, even when only one page is shown; other documents are not fetched.

Select an underlined occurrence to see candidate help scoped to that exact source position. A proposed citation destination is shown as a label, without an inferred link. Printed abbreviation-table rows are labelled as proposals; the view does not fetch and independently verify their table pages. Select a printed reference row to see its exact source location and unresolved body pairing. A cross-document reference opens only when it names an exact document, passage, occurrence and bound leaf. Similar digits or words do not create a link.

The stable deep link uses `/reading-help/corpus/?catalogue=…&family=…&document=…&unit=…`, with optional `occurrence=…`. A workbench link also carries `catalogue_sha256` and `catalogue_bytes`; the reader checks both before opening a document. A workbench manifest may declare `reading_help.catalogue` and up to one bounded `targets_by_case` sidecar per case. Its `okf-reading-help-workbench-targets.v1` sidecar maps an exact selected `record_id` to `family`, `document_id` and `unit_id`. Only the current case's sidecar is fetched, checked against its SHA-256 and byte count, and limited to 32 KiB and 64 targets. The corpus is fetched only after following the link. Records without an exact target remain unlinked.

The earlier [bounded reading aid](../reading-help/) remains available for `okf-reading-help.v1` manifests. Where a reviewed manifest links a body marker and reference row through the same card's occurrence IDs, **Other occurrences for this reference** navigates between them. This does not change the source text or decide whether the reference applies.

Both views are independent experimental publications. Their source-verified spans establish transport and extraction identity only. Candidate explanations remain unreviewed, and neither view gives an individual entitlement decision.

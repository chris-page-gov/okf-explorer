Trace a complex ELS API question

Question
When requesting indicator data, which geography and date filters can a client plan, and what evidence limits apply to an answer?

The upstream wiki says this API is internal/private, is not intended for non-ONS web applications, may change without notice, and prevents cross-origin browser requests.

Bundle identity: https://chris-page-gov.github.io/okf-els-api/okf-explorer.json · version 0.3.0 · OKF Core 0.3 · snapshot els-wiki-2026-07-20.

Worked answer from the pinned records

Date filters

The reviewed data route records `time` as latest, earliest, all, one date or a comma-separated inclusive range. `timeNearest` selects none, latest, earliest or any when a date falls outside an indicator's range. The recorded defaults are latest and none. See the pinned wiki page and reviewed data operation.

Geography filters

The reviewed data route records `geo` as one or more comma-separated geography-level keys or GSS codes, `geoExtent` as a parent GSS code, and `geoCluster` as a statistical cluster. Their recorded defaults are all. A separate `/api/v1/geo/lookup/{code}` route takes a GSS code and is described as returning one GeoJSON feature; it has no query parameters in this review. See the pinned geography page, data operation and single-area lookup.

Conflicts and evidence limits

The wiki says the data route's `hasGeo` default is all, while the pinned application review records any. The wiki also contradicts itself about the `includeNames` name/default; the reviewed route accepts `includeNames` and records true. Keep those differences visible rather than choosing a live truth. Read the hasGeo default finding and includeNames finding.

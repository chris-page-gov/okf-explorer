- Keep OKF v0.2 core separate from optional Explorer, semantic, large-corpus,
  federation, Foundry, and domain profiles.
- Preserve stable source-native identifiers, versions, routes, source roles,
  jurisdictions, observation times, derivation, rights, access, freshness,
  coverage, lifecycle, limitations, and evidence.
- Keep official, normalized, rule-derived, inferred, model-assisted,
  expert-asserted, historical, rejected, and editorial-example assertions
  distinguishable where applicable.
- Give every new material directed relationship an absolute assertion ID,
  absolute source/predicate/target IRIs, validated local routes, a governed
  relationship kind, preferred and inverse labels, status, scope, authority,
  derivation, observation time, structured evidence and rights. Generate the
  direct triple and its reified

  local shared schema before recording semantic conformance. Sampling is an
  audit aid, not a producer conformance gate.
- Never infer identity, equivalence, authority, licence, completeness,
  verification, or applicability from a similar label, public URL, confidence
  score, catalogue membership, or generated relationship.

- Apply {{DOMAIN_SPECIFIC_SAFETY_AND_NON_ADVICE_RULES}}.
- Never store or expose secrets, credentials, signed URLs, real personal data,

## Repository workflow

1. Classify the request as query, review, authoring, acquisition, evaluation,
   or publication.
2. Trace the requested outcome through authored inputs, generators, artifact
   planes, consumers, tests, and public routes using
   {{DEPENDENCY_OR_CHANGE_IMPACT_TOOL}}.
3. Make the smallest authored change.
4. Run the narrowest relevant deterministic check.
5. Review and cross-check the declared tooling, then regenerate affected
   outputs with the approved exact locked command. Never pass an unreviewed
   declaration to a shell.
6. Run check mode and the applicable full suite.
7. Inspect semantic and generated diffs, counts, identifiers, links,
   assertions, manifests, and checksums.
8. Update {{LOCKSTEP_DOCUMENTATION_FILES}} in the same change.
9. Report checks run, checks not run, remaining gates, working-tree state, and
   whether publication changed.

Do not create a remote, commit, push, open a pull request, enable CI, make a
paid call, acquire source bodies, or publish unless the user explicitly asks
and the recorded repository authority permits it.

## Query and large-corpus rules

- Read the declared descriptor before following entry points.
- Use overview, analysis, static search, record locator, and route adjacency in
  that order; load only relevant shards.
- Cite routes, source URLs, authority, derivation, time, confidence, rights,
  and limitations that support the answer.
- State which relationship or datapack planes were not checked.
- Do not call live APIs unless the task explicitly requires it and the source,
  access, rate, rights, privacy, and retention contracts permit it.

## Acquisition and enrichment rules

- Separate live acquisition from deterministic compilation.
- Use bounded allowlists, immutable attempts, external caches, rate limits,
  explicit retries, and a terminal outcome for every selected item.
- Never shrink a denominator or erase a failure to make reconciliation pass.
- Record model/method identity, input evidence, output status, available cost
  evidence, and independent evaluation for model-assisted artifacts.

## Code review rules

- Flag generated-only edits without the corresponding authored change.
- Flag source or assertion authority upgrades unsupported by direct evidence.
- Flag completeness claims without a reconciled denominator.
- Flag publication, release-grade, legal/medical/official, rights, or
  verification claims not bound to their exact evidence and gate.
- Flag consumer-visible changes without the relevant locked-consumer and
  journey checks.
